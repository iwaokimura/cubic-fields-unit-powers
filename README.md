# cubic-fields-unit-powers

PARI/GP and SageMath scripts accompanying

> I. Kimura and H. Umemoto,
> *On explicit units in a family of cubic fields and the arithmetic of curves
> arising from powers of these units*.

This is the sequel to
[cubic-fields-explicit-units](https://github.com/iwaokimura/cubic-fields-explicit-units)
(the scripts of the first paper). For an integer `b != 0, 1` let `K_b` be the
cubic field generated by the unique real root of `f_b(x) = x^3 - 3bx - b^3`,
`eta_0` its fundamental unit, and `eta_b = ((b+1) - theta)^(-1)`; write
`eta_b = eta_0^n(b)`. The paper proves that deciding `q | n(b)` is a question
about integral points of a plane curve `C_q` of degree `2q` and genus
`C(q-1,2)`, determines `n(b)` for `|b| <= 10^30`, determines the rational
points of `C_4` by quadratic Chabauty, and shows that `K_{-1} = K_5` is the only
coincidence `K_b = K_c` that does not involve a parameter beyond `10^30`.

These scripts are the computations behind the numerical statements in the
paper. **They verify; they do not prove** -- except where the paper says
explicitly that a step of a proof is an exact machine computation, in which
case the script named there is that step. Every script prints a pass-or-fail
verdict for each assertion it is meant to establish, and every script in this
repository terminates with 0 failures, with two deliberate exceptions kept as
records of the research trail: `check-mwsieve.gp` (a diverging sieve schedule,
superseded by `check-mwsieve-schedule.gp`) and `check-c4-globalheight.sage`
(its gate asserts a hypothesis the experiment *refuted* -- the recorded RED is
the finding that redirected the height computation).

## Independence from the Magma implementations

The library `padic/` is a SageMath implementation of Tuitman's algorithm and
of the quadratic Chabauty method, written **from the papers** -- J. Tuitman,
*Counting points on curves using a map to P^1* (Math. Comp., 2016/2017);
J. S. Balakrishnan and J. Tuitman, *Explicit Coleman integration for curves*
(Math. Comp., 2020); Balakrishnan--Dogra--Mueller--Tuitman--Vonk, *Explicit
Chabauty--Kim for the split Cartan modular curve of level 13* (Ann. of Math.,
2019) -- independently of the existing Magma implementations. The project's
working rule, recorded per experiment in the authors' research log, was to
derive each step from the paper and write its gate before consulting any
upstream source.

## Requirements

* PARI/GP for the `.gp` scripts. The runs reported in the paper were made
  with **PARI/GP 2.17.4**.
* SageMath for the `.sage` scripts and the `padic/` library. The runs were
  made with **SageMath 10.7**, whose linked libpari is a separate build
  (2.17.1 here); the suite records both versions.
* Magma, for one file only: `c4-regmodel.m`, the input that produced the
  regular model of `C_4` over Z_2 which the paper uses as an answer key
  (Section 9.5), with its output in `c4-regmodel.out`. It runs in the free
  Magma Online Calculator in under a second. It is not part of the suite, and
  nothing else in this repository needs Magma.

Run a single script from the repository root (so that `padic/` is importable):

```
gp -q --default parisize=2G <script>.gp < /dev/null
sage <script>.sage
```

To run the twenty-nine-script suite:

```
./run-e020-e040-suite.sh
```

To run everything in parallel with per-script logs and a summary:

```
J=12 ./run-all.sh
```

Two scripts have external inputs. `check-c4-2desc.gp` reads Denis Simon's
`ell.gp` as shipped with SageMath; set `SIMON_ELL` to its path (`run-all.sh`
locates it automatically). `check-c4-sieve.gp` reads `c4-qc-leftovers.txt`,
the leftover-point table that `check-c4-endgame.sage` writes; the committed
copy of that file is the one the paper uses, and `run-all.sh` orders the two
scripts so the sieve reads a freshly regenerated copy.

Some scripts allocate a larger PARI stack and print a warning saying so; that
is expected. The long runs (`check-e028-sweep.gp`, `check-qpow.gp`,
`check-c4-qc.sage`, `check-rho-tailbound.sage`, among others) take minutes
each.

The `E0nn` labels in the script headers are identifiers from the authors'
internal research log and can be ignored.
